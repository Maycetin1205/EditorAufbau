# Verknuepfte Quellen — Paket 3: Bindung mit Quellenangabe

> Plan, kein Gesetz. Bei Widerspruch gewinnen CLAUDE.md und der Nutzer.
> Stand 2026-07-27. Version 0.1.1 -> **0.2.0** (Minor: neue Faehigkeit,
> abwaertskompatibel).

## Overview

Eine bindbare Stelle kann heute nur Felder ihrer EIGENEN Datenquelle zeigen —
der Quelle des Bausteins bzw. des naechsten Vorfahren mit `acceptsDataSource`.
Paket 3 erweitert die Bindung um die Angabe, AUS WELCHER Quelle das Feld kommt:
gespeichert als `quelleId::feldcode`. Damit kann eine Tabellenspalte oder eine
Karten-Stelle einen Wert aus einer **verknuepften** Quelle zeigen (Verknuepfung =
das Modell aus Paket 1, gepflegt in der Steuerung seit Paket 2).

Paket 3 ist die EDITOR- und MODELL-Haelfte: Auswahl, Speicherung, Vorschau,
Preflight. Der Laufzeit-Aufloeser und der Export-Anschluss (`FF_SOURCE_LINKS`,
SEFILELOOP fuer die verknuepfte Quelle) sind **Paket 4** und ausdruecklich NICHT
Teil dieses Plans.

## Problem Statement

1. **Der Bediener kann den Fall nicht ausdruecken.** Sein Beispiel (belegt am
   eigenen Bestand): Tabelle auf `terminplaner`, eine Spalte soll `Notiz`
   (`128_350`) aus `kundenhaustiere` zeigen. Beide Quellen tragen
   `Adressnummer` an `10_8` — der Schluessel ist da, die Verknuepfung laesst
   sich anlegen, aber die Spalte kann das Feld nicht waehlen.
2. **Ein Feldcode allein ist nicht eindeutig.** In genau diesem Bestand
   kommen FUENF Klarnamen in beiden Quellen vor (Tiername, Tierart, Rasse,
   Geburtsdatum, Behandlung) — bei UNTERSCHIEDLICHEN Codes (`Tiername` ist
   `78_30` im Terminplaner, `18_30` in Kundenhaustieren). Ohne Quellenangabe
   waere jede Bindung an eine Fremdquelle geraten. Das Aktionsketten-Modell
   hat dieselbe Erkenntnis bereits verarbeitet: `ActionParamBinding` traegt
   seit langem ein `dataSourceId` neben dem Feldcode, mit genau dieser
   Begruendung (`src/core/data/aktionen.ts`).
3. **Der Bestand ist ungenutzt.** `findLink`, `istBrauchbar`,
   `paareAusSicht`, `vollstaendigePaare` in `core/data/sourceLinks.ts` sind seit
   Paket 1 gebaut und getestet, aber kein Produktionscode ruft sie. Die
   Verknuepfungen, die der Bediener seit Paket 2 anlegen kann, haben bis heute
   keine Wirkung.

## Solution Architecture

**Eine Konvention, eine Stelle.** Der Feldcode-String bekommt eine optionale
Quellen-Vorsilbe:

```
"128_350"                   -> Feld der EIGENEN Quelle (unveraendert, wie bisher)
"kundenhaustiere::128_350"  -> Feld der verknuepften Quelle
```

Die Wahl faellt auf eine Vorsilbe im String (nicht auf eine zweite Prop), weil
der Feldcode heute an ZWEI voellig verschiedenen Orten wohnt:

| Traeger | Beispiel | Wo |
| --- | --- | --- |
| `bindableSpots` -> Prop `<prop>Field` | `valueField`, `titleField` | Formularfeld (1 Stelle), Karte (8 Stellen) |
| `listenBindung` -> Schluessel IM Listen-Eintrag | `spalten[i].feld` | Tabelle (Spaltenzahl erst zur Laufzeit bekannt) |

Beide halten einen **einfachen String**. Eine Vorsilbe reist deshalb durch beide
Traeger, ohne dass ein zweites Feld, ein zweites Attribut oder eine Migration
entsteht. Eine Parallel-Prop (`<prop>FieldSource`) haette fuer die Listen-Variante
gar keinen Ort — die Tabelle muesste ihr Spalten-Modell aendern (Regel 10:
kein Umbau, wo eine Konvention genuegt).

**Abwaertskompatibel per Konstruktion:** ein Code ohne `::` bedeutet
unveraendert „eigene Quelle". Bestehende Masken, Speicherstaende und der
Referenzabzug bleiben unberuehrt; es gibt keine Schema-Migration.

**Die EINE Stelle** ist `core/blocks/BlockDefinition.ts` — dort wohnen bereits
`bindingProp`/`bindingAttr` als „das Helferpaar fuer die EINE
Bindungs-Attribut-Form" (ARCHI Abschnitt 3). Bauen und Zerlegen der
qualifizierten Form kommen daneben. Kein anderer Leser darf `::` selbst
suchen oder zusammensetzen.

## Implementation Details

### 1. Die Konvention

**File**: `src/core/blocks/BlockDefinition.ts` (207 Zeilen)

**Current state**: `bindingProp(prop)` -> `<prop>Field`, `bindingAttr(prop)` ->
`<prop>field`. Beide sind als „DIE eine Stelle" dokumentiert.

**Modifications** (unmittelbar hinter `bindingAttr`, damit die Konvention an
einem Ort steht):

- Konstante fuer das Trennzeichen `::`.
- Funktion, die aus (Quellen-id, Feldcode) den qualifizierten Wert baut;
  liefert bei LEERER Quellen-id den nackten Feldcode zurueck (die eigene
  Quelle wird nie qualifiziert — sonst gaebe es zwei Schreibweisen fuer
  dasselbe und der Export waere nicht mehr deterministisch).
- Funktion, die einen gespeicherten Wert zerlegt in `{ quelleId, code }`, wobei
  `quelleId === ''` „eigene Quelle" heisst. Defensiv: mehrfaches `::`,
  fuehrendes/abschliessendes `::`, leerer Code -> als NICHT qualifiziert
  behandeln (nackter Code), nie werfen. Begruendung im Kommentar: ein
  handgepfuschter Speicherstand darf den Editor nicht anhalten (Muster der
  `sanitize*`-Funktionen).

**Risiko + Gegenmassnahme**: enthaelt eine Quellen-id selbst `::`, ist die Form
mehrdeutig. Heutige ids sind Slugs (`terminplaner`, `kundenhaustiere`), aber der
Bestand ist Nutzerdaten. Darum zusaetzlich:

**File**: `src/core/data/dataSources.ts`

- `sanitizeDataSources` verwirft Eintraege, deren `id` das Trennzeichen
  enthaelt (dieselbe Behandlung wie heute schon fuer leere/doppelte ids), und
  die id-Erzeugung im Steuerungs-Formular schliesst es aus. Damit ist die
  Eindeutigkeit an der Quelle garantiert, nicht beim Lesen erraten.

### 2. Welche Quellen sind erreichbar

**File**: `src/core/data/sourceLinks.ts` (128 Zeilen)

**Current state**: richtungsfreies Verknuepfungs-Modell mit `findLink`,
`istBrauchbar`, `paareAusSicht`, `vollstaendigePaare`. Reine Daten, kein DOM.

**Modifications**: eine LESENDE Funktion ergaenzen, die zu einer Hauptquelle
alle ueber eine brauchbare Verknuepfung erreichbaren Quellen liefert.

- Nutzt `istBrauchbar` (halbfertige Verknuepfungen zaehlen nicht) und die
  richtungsfreie Logik von `findLink` — kein neuer Vergleich, keine Kopie.
- **Nur EINE Stufe.** Ist A mit B und B mit C verknuepft, ist C von A aus
  NICHT erreichbar. Begruendung: Regel 10 (kein echter zweiter Fall) und
  Regel 4 (mehrstufige Ketten waeren zur Laufzeit ein Nachschlage-Baum, dessen
  Kosten und Fehlerwege niemand belegt hat). Der Kommentar sagt das
  ausdruecklich, damit es niemand fuer eine Luecke haelt.
- **Deterministische Reihenfolge**: Reihenfolge der Verknuepfungs-Liste,
  Duplikate raus. Wichtig, weil daraus die Reihenfolge im Picker entsteht.
- Quellen-ids ohne auffindbare Quelle werden ausgelassen (kaputte Verknuepfung
  = kein Absturz; der Preflight meldet sie).

### 4. Der Feld-Picker zeigt Gruppen

**File**: `src/editor/canvas/FieldPicker.tsx` (110 Zeilen)

**Current state**: bekommt `sourceName: string` + `fields: DataSourceField[]`
und rendert eine flache Liste mit der Kopfzeile „<Stelle> · Feld aus <Quelle>",
darueber „— nicht gebunden —".

**Modifications**:

- Statt einer Quelle eine Liste von Gruppen: je Gruppe die Quelle und die
  Markierung „eigene / verknuepft". Eigene Quelle IMMER zuerst, danach die
  verknuepften in der Reihenfolge aus Abschnitt 2.
- Je Gruppe eine Zwischen-Ueberschrift mit dem KLARNAMEN der Quelle
  (Regel 3: nie die id). Bei verknuepften Gruppen zusaetzlich der Hinweis,
  ueber welches Feld verknuepft ist — der Bediener soll sehen, WARUM diese
  Quelle angeboten wird (Text aus den vollstaendigen Schluesselpaaren, in
  Klarnamen).
- `onPick` liefert weiterhin EINEN String: bei Fremdquellen den qualifizierten
  Wert (gebaut ueber die Funktion aus Abschnitt 1, nie per String-Konkatenation
  im Picker).
- Gibt es keine Verknuepfung, sieht der Picker aus wie heute (eine Gruppe).
  Kein leerer Bereich, kein Hinweistext — der Nutzer will keine
  Erklaer-Texte in der Oberflaeche (Memory-Notiz, Entscheidung 2026-07-22).
- Der aktuell gebundene Eintrag wird ueber den ZERLEGTEN Wert erkannt, damit
  der Haken bei einer Fremdbindung in der richtigen Gruppe steht.

### 5. Vorschau im Editor

**File**: `src/editor/canvas/useLitElement.ts` (139 Zeilen, Zeilen ~113–130)

**Current state**: fuer jede gebundene Stelle wird der Klarname des Felds als
DOM-Property gesetzt (Bindungs-Vorschau statt erfundener Werte). Aufgeloest wird
ausschliesslich gegen `dataSource` (die eigene Quelle); ist das Feld dort
unbekannt, bleibt die Stelle leer.

**Modifications**:

- Den gespeicherten Wert zerlegen; bei gesetzter Quellen-id gegen DIESE Quelle
  aufloesen (aus dem `DataSourceStore` ueber die Erreichbarkeits-Funktion aus
  Abschnitt 2 — nur erreichbare Quellen, damit eine verwaiste Bindung nicht
  heimlich doch Werte zeigt).
- **Fremdfelder werden markiert.** Angezeigt wird `Klarname` + ein kleines
  Zeichen (` ↗`), NICHT der Quellenname. Entscheidung des bauenden Agenten
  2026-07-27 (der Nutzer hat die Frage ausdruecklich zurueckgegeben):
  ausgeschrieben („Notiz (Kundenhaustiere)") waere die Vorschau deutlich
  breiter als der spaetere echte Wert — die Karte saehe im Editor anders aus
  als in SoftEngine, und „was du siehst, IST der Export" ist der Nordstern.
  Das Zeichen warnt, ohne die Breite zu verfaelschen; WELCHE Quelle es ist,
  zeigt der Picker beim Klick. Die Markierung entsteht an EINER Stelle, damit
  sie sich in einem Zug aendern laesst, wenn der Nutzer sie zu unauffaellig
  findet.
- Ist die Bindung nicht aufloesbar (Quelle weg, Verknuepfung geloescht, Feld
  weg), bleibt es beim heutigen Verhalten: statischer Text ohne Markierung,
  die Bindung bleibt gespeichert. Der Preflight sagt beim Export, was fehlt.

**Nicht betroffen — bewusst**: die Spalten-UEBERSCHRIFT der Tabelle. Beim Binden
wird sie heute immer auf den Feld-Klarnamen gesetzt (Nutzer-Entscheidung
2026-07-27, BlockHost ~276–287). Sie bleibt der reine Klarname OHNE Zeichen und
ohne Quellenzusatz: die Ueberschrift ist echter Masken-Inhalt, den der Bediener
in SoftEngine sieht — dort hat kein Editor-Hinweis etwas zu suchen (Regel 1).

### 8. Uebergangs-Sperre bis Paket 4 (wichtig)

**File**: `src/export/preflight.ts`

Nach Paket 3 kann der Bediener eine Fremdbindung SETZEN, aber die Laufzeit kann
sie noch nicht AUFLOESEN (das ist Paket 4). Ein Export in diesem Zwischenstand
ergaebe eine Maske, die an dieser Stelle stumm leer bleibt — genau das, was
Regel 4 verbietet.

Darum blockt der Preflight den Export, solange eine qualifizierte Bindung im
Baum steht, mit Klartext in der Art: „Diese Stelle holt ihren Wert aus einer
verknuepften Quelle. Die fertige Maske kann das noch nicht laden — der Teil
kommt im naechsten Paket." Die Sperre ist BEFRISTET und wird in Paket 4
ersatzlos entfernt; sie steht als eigener, klar benannter Abschnitt im Code,
damit sie dort nicht vergessen wird. Alternative waere, Paket 3 und 4 nur
gemeinsam auszuliefern — die Sperre ist billiger und erlaubt dem Nutzer, die
Bedienung schon abzunehmen.

## Technical Considerations

- **Pattern Usage**: Registry-getrieben (Regel 2) — `bindableSpots` und
  `listenBindung` bleiben die einzigen Quellen der Wahrheit; nirgends ein
  Bausteintyp-Vergleich, nirgends ein Baustein-Import in Editor-Code. Die
  Konvention wohnt bei `bindingProp`/`bindingAttr` (Regel „eine Stelle").
- **Regel 3**: sichtbar sind Klarnamen (Quellenname, Feld-Klarname), die
  Quellen-id bleibt unsichtbar — auch in den Gruppen-Ueberschriften.
- **Regel 4**: jeder neue Fehlerweg hat eine Preflight-Meldung mit Klartext;
  nichts wird still uebersprungen.
- **Regel 7**: keine erfundenen Werte, keine Erklaer-Texte in der Oberflaeche.
- **Regel 10**: nur EINE Verknuepfungs-Stufe; Inspector-Feldlisten bleiben
  unberuehrt; kein Umbau des Spalten-Modells.
- **Deckel 500 Zeilen**: BlockHost (494) wird durch Abschnitt 3 kleiner, nicht
  groesser. Nach dem Umzug erneut messen; `Editor.ts` (464) wird nur lesend
  angefasst.
- **Export-Bytes**: solange keine Maske eine Fremdbindung nutzt, aendert sich
  KEIN exportiertes Byte (Vorsilbe optional). Der Referenzabzug muss gruen
  bleiben, ohne erneuert zu werden — das ist die Probe darauf, dass die
  Abwaertskompatibilitaet echt ist. Wird er rot, ist etwas falsch.
- **Edge Cases**: `::` in einer Quellen-id (Abschnitt 1 verhindert es an der
  Quelle) · Verknuepfung wird geloescht, waehrend eine Bindung darauf zeigt
  (Preflight meldet, Vorschau fallt auf statischen Text zurueck) · zwei
  Verknuepfungen zwischen denselben Quellen (`findLink` nimmt die erste
  brauchbare — heutiges Verhalten, bleibt) · Fremdbindung an einem Baustein
  OHNE eigene Quelle (S1b-Fall „Bindung ohne Datenquelle" greift schon) ·
  Quelle des Bausteins wird umgestellt, Fremdbindung passt nicht mehr zur neuen
  Verknuepfungslage (Preflight „Verknuepfung fehlt").

## Type Definitions

- **Zerlegtes Bindungsziel**: `{ quelleId: string; code: string }` —
  `quelleId: ''` heisst „eigene Quelle". Neben `BindingProp`/`BindingAttr` in
  `BlockDefinition.ts`.
- **Picker-Gruppe**: Quelle + Kennzeichen „eigene" + optionaler
  Verknuepfungs-Hinweis (Klarnamen der Schluesselfelder). Nur Editor-UI, lebt
  bei `FieldPicker`/`FeldBindung`.
- Keine Aenderung an `SourceLink`, `DataSource`, `Spalte`, `BlockNode`,
  `PersistedState` — und damit keine Schema-Migration.

## Backward Compatibility

- Nackter Feldcode = eigene Quelle: alle bestehenden Bindungen gelten
  unveraendert weiter, kein Migrationsschritt, `CURRENT_SCHEMA_VERSION` bleibt.
- Alte Speicherstaende mit kaputten Werten fallen ueber das defensive Zerlegen
  auf „nackter Code" zurueck, statt zu werfen.
- Export-Bytes bleiben identisch, solange keine Fremdbindung genutzt wird
  (Referenzabzug als Beweis).
